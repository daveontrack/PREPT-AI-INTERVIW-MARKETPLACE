# Ethiopian Sign Language — dataset strategy

Operational version of the research plan for training the EthSL recognition
model behind this service. **No trained model can be credible without this
step** — an ASL model will not recognize EthSL, and the published EthSL
numbers (≈94% signer-dependent vs ≈73% signer-independent, Sci. Reports 2025)
show that generalization to unseen signers is the real challenge.

## 1. Existing research datasets

| Dataset | What it is | Access | Use it for |
| --- | --- | --- | --- |
| **A — EthSL isolated-sign corpus** (Scientific Reports 2025, [s41598-025-19937-0](https://www.nature.com/articles/s41598-025-19937-0)) | 5,600 annotated sign videos, 7 signers; MediaPipe Holistic + CNN-LSTM/LSTM/BiLSTM/GRU baselines | Raw videos **not public** (privacy/institutional). Contact the authors; ask about derived landmark files — those would drop straight into this service's preprocessing contract | Model-design reference; possible landmark transfer |
| **B — CESLR** (Bahir Dar Univ. thesis 2024, [record](https://ir.bdu.edu.et/handle/123456789/16272); [Zenodo 10800699](https://zenodo.org/records/10800699)) | 1,320 sentence recordings, 30 sentences × 2 takes × 22 signers; CTC continuous recognition | Zenodo files **restricted** — verify licensing before any use | Continuous-recognition (Stage 2) reference |
| **C — EthSL alphabet research** ([NADRE 2413](https://nadre.ethernet.edu.et/record/2413)) | Real-time Ethiopian sign alphabet recognition (CV + motion sensors) | Repository record | Fingerspelling prototype before sentence work |

Access checklist before touching any of them:

- [ ] Written licensing terms allow your intended use (research vs product)
- [ ] Signer consent covers your deployment context (commercial app use is usually *not* covered)
- [ ] Annotation provenance: who labeled, which gloss set, how disputes were resolved
- [ ] If only derived landmarks are available: confirm they were produced with a documented landmark config so you can match it at serving time

**Do not** assume machine-translated Amharic/English labels are equivalent to
the signed meaning. Every gloss must be verified with EthSL users.

## 2. Pilot collection (the part you fully control)

When research-data access is blocked — which is the expected case — collect a
small pilot set first:

1. **Vocabulary first, sentences later.** Start with 30–80 glosses useful in
   interviews (greetings, "explain", "example", "database", "algorithm",
   "yes/no", numbers, name/place signs…), chosen **with** EthSL users and
   qualified annotators.
2. **Signers, not clips.** Record each gloss from ≥10 signers; more signers
   beats more repeats per signer for generalization.
3. **Variation is the point:** varied lighting, backgrounds, camera angles,
   distances, signing speeds, dominant hand, clothing/skin tones, glasses.
4. **Consent per signer** (recording + storage + model training + retention
   period, in writing, in a language the signer is fluent in). Store the
   consent id on every clip (see `data/annotations/annotations.csv`).
5. **Never** reuse interview-call recordings for training without separate,
   explicit consent — the app's transcripts and videos are off-limits by
   default.

Layout the intake under `data/`:

```
data/
├── raw/                  # videos (git-ignored; access-controlled)
│   └── {signer_id}/{clip_id}.mp4
├── landmarks/            # raw (un-normalized) landmark arrays, .npy per clip
├── annotations/
│   └── annotations.csv   # clip_id,signer_id,gloss,consent_id,split,notes
└── splits/               # generated by training/split_by_signer.py
```

## 3. Annotation rules

- One gloss per isolated-sign clip (Stage 1). Continuous sentences only after
  the isolated-sign model is reliable (Stage 2 → CESLR-style CTC).
- Glosses are **language-specific labels**, not English translations. Keep a
  canonical `models/vocabulary.txt` (one gloss per line) and validate every
  annotation against it: `python training/split_by_signer.py … --vocabulary models/vocabulary.txt`.
- Double-annotate ≥10% of clips and report inter-annotator agreement.

## 4. Evaluation protocol (non-negotiable)

- Split **by signer**, never by clip. A signer in training must never appear
  in validation/test. `training/split_by_signer.py` enforces this and fails
  loudly on leakage.
- Report both signer-dependent and **signer-independent** metrics — the gap
  between them is the number that matters.
- Isolated signs: top-1 accuracy per gloss + confusion matrix.
  Continuous: **WER**.
- Product metrics from the plan: prediction **latency** (target: usable
  result ≤ ~3 s after a phrase ends — the client sends 24-frame windows),
  candidate **correction rate** (share of entries edited before confirm),
  session reliability across reconnects.
- Calibrate the confidence threshold on held-out signers. The app currently
  flags predictions below **0.55** for manual review
  (`hooks/useSignLanguageRecognition.js`); retune it from your validation
  curve and update both sides together.

## 5. Fitting data into this service

- Training code lives here (`training/`), serving code in `app/` — keep the
  normalization contract (`app/preprocessing.py`) as the single source of
  truth; training must import it, not reimplement it.
- Export the trained model behind the `Predictor` interface
  (`app/inference.py`) with a `modelVersion` string; every transcript entry
  records it so quality regressions are traceable.
- Expand vocabulary only when the signer-independent eval holds up — bigger
  vocabularies with 5 signers produce confident, unusable models.
